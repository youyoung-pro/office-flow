# hwpx 법정 서식 원본 유지 채우기

## 목적과 원칙
법제처·소관부처가 배포하는 법정 별지 hwpx 서식은 조항·테두리·셀 병합이 법으로 정해진 형식이다.
Word 변환이나 재작성은 이 형식을 흐트러뜨린다. 그래서 이 스킬은 원본 hwpx의 구조를 그대로 두고,
값이 들어갈 셀의 텍스트에만 값을 덧붙인다. 지켜야 할 원칙은 다음과 같다.

1. `Contents/section*.xml`의 대상 셀 텍스트만 수정한다. `header.xml`, 조항 텍스트, 테두리, 셀 병합은 건드리지 않는다.
2. 값 셀은 라벨 문자열이 아니라 셀 좌표(rowAddr, colAddr)로 특정한다. 같은 라벨("성명(명칭)" 등)이 갑·을·공동명의자에 반복되기 때문이다.
3. hwp(구형 바이너리)는 직접 편집이 어렵다. hwpx로 받거나 변환한 뒤 편집한다.
4. 재압축 시 `mimetype`은 반드시 맨 앞·무압축으로 넣는다. 어기면 한글이 파일을 못 연다.

## 표준 절차

### 0단계 — 원본 서식 확보와 hwpx 변환 (파일이 없을 때)
법정 별지 서식은 반드시 국가법령정보센터에서 현행판을 새로 내려받는다. 업무 폴더에 남아 있는
구버전 사본을 재사용하지 않는다(별지 서식은 수시로 개정된다. 예: 행정심판법 시행규칙 별지는 2025. 9. 24. 개정).

1. 다운로드 경로: `law.go.kr/법령/한글법령명`(붙여쓰기)으로 법령 페이지를 열면 좌측 트리의 "서식" 항목에
   각 별지의 `.hwp` / `.hwpx` / `.pdf` 직링크가 있다. Claude for Chrome으로 해당 링크를 클릭해 내려받고,
   사용자 Downloads 폴더를 연결해 파일을 회수한다. 본문 중 "별지 제N호서식" 파란 링크로도 서식 뷰에 진입할 수 있다.
2. 함정 1 — 확장자 위장: law.go.kr의 `.hwpx` 링크도 실제 내용은 구형 hwp(OLE2, 매직 `D0 CF 11 E0`)로
   내려오는 경우가 있다. 받은 파일의 앞 4바이트를 확인하라. `PK`면 진짜 hwpx, `D0CF11E0`이면 hwp다.
3. 함정 2 — 임시 파일명: 브라우저 자동 클릭 다운로드는 Downloads에 `UUID.tmp` 이름으로 남을 수 있다.
   여러 건을 받았으면 python `olefile`로 `PrvText` 스트림(UTF-16LE)을 읽어 어떤 서식인지 식별한 뒤 개명한다.
4. hwp → hwpx 변환: 클라우드에서는 hwp-render-convert 스킬(rhwp)로 먼저 변환을 시도할 수 있다.
   다만 관공서 제출본의 형식 적합성은 한글 확인본이 기준이므로, 변환이 실패하거나 결과가 의심되면
   대표 PC의 한글로 변환한다. computer use에서 `computer_resolve_access`에 "한글 2024"(또는 "한글 2020")를
   요청하면 `hwp.exe`가 resolve된다(런처인 "한컴오피스"만 승인하면 실제 창이 마스킹되므로 반드시 한글 앱
   자체를 승인받는다). 한글에서 Alt+O(불러오기) → 전체 경로 입력 → Enter → Alt+V(다른 이름으로 저장) →
   파일 형식 "한글 표준 문서(*.hwpx)" 선택 → 저장. 여러 건이면 같은 창에서 반복한다. 작업 후 한글 창은
   열어 두어 사용자가 눈으로 확인하게 한다.
5. 내려받은 원본 hwp·hwpx 쌍은 사건 폴더의 서식 보관 폴더(예: 90. 법령서식_참고)에 [원본서식] 접두어로 보존하고,
   채우기 작업은 반드시 사본으로 한다.

### 1단계 — 레이아웃 파악 (반드시 먼저)
서식마다 "라벨 옆 빈칸에 값을 쓰는 셀"과 "값 셀이 따로 분리된 구조"가 섞여 있다. 무엇을 어디에 넣을지
확정하기 전에 실제 구조를 본다. 번들 스크립트로 셀 좌표와 텍스트를 덤프한다.

```bash
python scripts/hwpx_fill.py dump 원본.hwpx
```

출력은 `row{R} col{C} :: '셀 텍스트'` 형식이다. 여기서 값을 넣을 항목의 (row, col)을 고른다.
표의 라벨 순서가 헷갈리면 압축을 풀어 `Preview/PrvText.txt`(항목 순서)와 `Preview/PrvImage.png`(실제 레이아웃 이미지)를 함께 확인한다.

### 2단계 — 값 매핑 작성
채울 항목을 `"row,col": "값"` 형태의 JSON으로 만든다. 확인되지 않은 항목(예: 차대번호)은 넣지 않고 비워 둔다.

```json
{
  "5,2": "최종희",
  "5,8": "660315-1000512",
  "7,2": "서울특별시 성북구 돌곶이로40길 46, 708동 2103호",
  "18,8": "2026. 7. 25."
}
```

### 3단계 — 채우고 재패키징
스크립트가 대상 셀의 마지막 텍스트 노드 뒤에 값을 덧붙이고, mimetype 규칙을 지켜 다시 압축한다.

```bash
python scripts/hwpx_fill.py fill 원본.hwpx 결과.hwpx fills.json
```

값 셀이 완전히 비어 텍스트 노드가 없는 서식이면, 스크립트가 해당 셀 첫 문단의 런에 텍스트 노드를 새로
삽입한다. 이때도 기존 문단·런 속성(paraPrIDRef, charPrIDRef)은 보존한다.

### 4단계 — 검증
hwpx는 LibreOffice로 렌더링되지 않으므로 텍스트·구조로 검증한다. 스크립트의 verify가 XML 적합성,
mimetype(맨 앞·값 `application/hwp+zip`), 채운 셀 값을 확인한다. 눈으로 볼 미리보기가 필요하면
hwp-render-convert 스킬로 PDF·PNG 검수 렌더를 만들 수 있다.

```bash
python scripts/hwpx_fill.py verify 결과.hwpx --expect fills.json
```

마지막 레이아웃 확인은 한글(HWP)에서 파일을 한 번 열어 눈으로 점검하도록 사용자에게 안내한다.
Preview 썸네일은 편집 후 옛 이미지로 남지만 한글에서 열면 본문이 재렌더되므로 무시해도 된다.

### 5단계 — 체크박스·플레이스홀더 처리 (필요한 서식만)
법정 서식의 `[  ]` 체크박스와 `○○행정심판위원회`, `○○시ㆍ도` 같은 플레이스홀더는 값 "덧붙이기"가 아니라
해당 문자열의 "치환"이 필요하다. 이때도 원칙은 같다. 반드시 셀 좌표로 대상 셀을 특정한 뒤, 그 셀 블록
안에서만 최소 범위로 문자열을 치환한다(문서 전체 치환 금지 — 처리절차 표 등에 같은 플레이스홀더가 반복된다).

- 체크 표시: 해당 셀에서 `[  ] 대상항목` → `[√] 대상항목`. 같은 셀에 `[  ]`가 여러 개면 대상 항목 문자열까지
  포함해 유일하게 매칭시킨다. 셀 텍스트가 `<hp:fwSpace/>` 등으로 쪼개져 있을 수 있으니 먼저 dump나
  텍스트 노드 원문을 확인하고 실제 XML 문자열 그대로 치환한다.
- 플레이스홀더: `○○행정심판위원회` → `서울특별시행정심판위원회`처럼 관할 기관명으로 교체. 근거 조문이 든
  본문 문장 셀(예: "…에 따라 위와 같이 청구합니다. 년 월 일 … ○○행정심판위원회 귀중")에 섞여 있어도
  플레이스홀더 부분만 바꾸고 조항 문언·날짜 공란은 건드리지 않는다.
- 선택지가 서식 고정 문언인 경우(예: "특별자치도지사ㆍ특별자치시장ㆍ시장ㆍ군수 또는 구청장 귀하")는
  치환하지 않고 그대로 두며, 제출처는 사용자에게 안내한다.
- 확정되지 않은 선택(연장/분납 구분, 구술심리 여부 등)은 √를 넣지 말고 공란으로 남겨 사용자 결정 사항임을 보고한다.

### 6단계 — 긴 기재란의 별지 분리 (사무소 상시 규칙)
신청원인·신청사유·청구이유처럼 넣을 내용이 길어 서식 칸을 넘칠 우려가 있으면, 칸에 본문을 밀어 넣어
표를 늘어뜨리지 말고 반드시 별지로 분리한다. 셀이 늘어나면 법정 서식의 1면 레이아웃이 깨지기 때문이다.

1. 해당 칸에는 `[별지] 기재와 같음`만 기재한다.
2. 같은 hwpx 파일의 마지막에 새 페이지(첫 문단 `pageBreak="1"`)로 별지를 만든다. 구성:
   가운데 정렬 `[별 지]` 표제 → 항목 제목(예: 신 청 원 인) → 본문 문단들 → 가운데 정렬 `끝.`
3. 별지 문단의 서식 규칙(사무소 표준, 항상 적용):
   제목(표제·항목 제목)은 20포인트 굵게 가운데 정렬, 본문은 12포인트 양쪽 정렬(JUSTIFY), 자간은 전 항목 -5.
   글꼴 얼굴은 원본 서식의 본문 셀 charPr을 클론하여 동일하게 하되, 원본 선언은 절대 수정하지 않는다.
   구현: 새 charPr 2개(20pt·12pt, textColor #000000 명시)와 새 paraPr 2개(CENTER·JUSTIFY, paraPr 0 클론)를
   header.xml 각 목록의 "맨 끝"에만 추가하고 itemCnt를 +2씩 올린다.
   경고: 새 선언을 목록 중간에 끼워 넣으면 한글이 참조를 인덱스로 밀려 읽어 뒤쪽 선언(하이퍼링크 파랑 등)이
   적용되는 사고가 난다(실사례: 별지 전체가 파란색). 반드시 마지막 id 뒤에 붙여 id=순번을 유지한다.
   행정심판 계열 별지에는 증거(소명자료) 목록을 넣고, 본문 각 주장 문단에 해당 증거를 괄호로 인용해
   주장-증거를 연결한다(예: "…완납하였고(갑 제8호증 과세증명서)").
4. 기준: 값이 대략 2줄(약 90자)을 넘거나 번호 매긴 여러 항으로 구성되면 별지로 분리한다.
   성명·주소·금액·날짜 같은 한 줄 값은 칸에 그대로 넣는다.
5. 채운 뒤 한글에서 열어 보았을 때 칸의 글자가 한 줄로 눌려 겹쳐 보이면(셀이 자동 압축된 경우),
   그 칸도 "[별지] 기재와 같음"으로 바꾸고 별지로 옮긴다(실사례: 집행정지신청서 신청취지 칸).
6. 중간 길이 값은 끊어서 항목화한다. 별지로 뺄 만큼 길지는 않으나 한 줄에 담기에는 긴 값(대략
   한 줄에서 두 줄 사이)을 한 문장으로 밀어 넣으면 한글의 표 안 줄바꿈이 단어 단위로 끊기지 않아
   읽기 어려워진다. 이런 값은 쉼표나 "및", "그리고"가 들어가는 자리에서 끊어 두세 항목으로 나누고
   각 항목 앞에 글머리 기호를 붙인다. 예를 들어 "학사·인사·재정 관련 사업 전반 심의 및 단계평가
   대응 총괄"은 "학사·인사·재정 관련 사업 전반 심의"와 "단계평가 대응 총괄" 두 항목으로 나눈다.
   목적은 서식을 채우는 것이 아니라 담당 공무원이 잘 읽게 하는 것이다. 다만 법정 문언이나 처분
   명칭처럼 원문 그대로 적어야 하는 값은 끊지 않는다.

### 7단계 — 문단 신설 시 글자 모양·줄나눔 캐시 규칙 (겹침 사고 방지, 2026-08-13 개정)
별지든 자유서식이든 hwpx에 문단을 새로 만들어 넣을 때(별지 본문, 탄원서·의견서 등 사무소 문서 전체)
반드시 다음을 함께 지킨다. 2026-08-13 구청장 탄원서 v2에서 이 규칙을 어겨 한글에서 본문 전체가
한 줄로 눌려 겹쳐 보이는 사고가 실제로 발생하였다(대표행정사 지적·시정).

첫째, 글자 모양은 사무소 표준을 따른다. 본문은 휴먼명조 12pt, 장평 100%, 자간 -5(ratio 100,
spacing -5), 글자색 #000000. 제목은 같은 글꼴 20pt 굵게. 기존 문서의 charPr을 클론하면 이 값이 이미
들어 있으므로 클론을 우선하고, 새 charPr을 만들 때는 ratio(장평) 100과 spacing(자간) -5를 반드시
명시한다. 장평·자간이 빠진 charPr을 새로 선언하지 않는다.

둘째, linesegarray(줄나눔 캐시)는 줄 단위로 분할 생성한다. 한글은 문단의 linesegarray 캐시를
신뢰하므로, 긴 문단에 lineseg가 1개뿐이면 본문 전체를 한 줄에 눌러 그려 글자가 겹친다. 12pt·자간 -5
기준 본문 폭(horzsize 약 48000~51000)에서 줄당 약 50자로 잡고, 문단 글자 수를 50으로 나눈 수만큼
lineseg를 만든다. textpos는 0, 50, 100… 으로 누적하고, 첫 줄 flags는 393216, 이후 줄은 1441792로
한다. vertpos는 문서 흐름을 따라 누적시키되 페이지 높이를 넘으면 0에서 다시 시작한다(근사값이어도
무방하나 줄 개수는 부족하면 안 된다 — 줄당 글자 수는 낮춰 잡는 편이 안전하다). 정상 개봉이 검증된
기존 산출물(행정심판청구서 v7)의 긴 문단이 이 구조다.

셋째, 검증 단계에 겹침 검사를 추가한다. 완성본에서 150자 이상의 hp:t를 가진 문단을 전수 조사하여
lineseg가 2개 미만이면 실패로 처리하고 재생성한다. 이 검사는 verify와 별도로 반드시 수행한다.

## 함정 체크리스트
- 새로 만드는 문단의 linesegarray는 줄 단위 분할 필수. 긴 문단에 lineseg 1개면 한글에서 글자가 한 줄로 겹친다(7단계).
- mimetype을 압축하거나 맨 앞이 아니면 한글이 인식하지 못한다. 반드시 `zip -X -0`로 먼저 넣는다(스크립트가 처리).
- 라벨 문자열로 치환하면 갑·을·공동명의자의 동일 라벨이 함께 바뀐다. 좌표로만 특정한다.
- 대상 셀이 유일한지 확인 후 치환한다(스크립트가 count 검사).
- 조항·서식·테두리는 수정 금지. 값만 덧붙인다.
- 값은 라벨 셀 서식(굵기 등)을 상속한다. 별도 서식이 필요하면 런을 추가하되 기존 속성은 보존.
- law.go.kr에서 받은 `.hwpx`도 내용이 hwp일 수 있다. 매직 바이트(`PK` vs `D0CF11E0`)를 반드시 확인.
- 같은 (row,col) 좌표가 본문 표·뒤쪽 안내 표·처리절차 중첩 표에 중복 등장한다. 스크립트는 첫 번째 일치
  셀을 채우므로, 대상 셀이 뒤쪽 표에 있으면 수동 처리로 전환한다.
- "청구 취지 및 청구 이유: 별지로 작성" 유형은 서식 칸에 본문을 밀어 넣지 말고, 6단계 규칙에 따라
  같은 hwpx 파일의 다음 페이지에 별지로 작성한다(별도 파일로 쪼개지 않는다).
- 표 칸의 중간 길이 값은 한 문장으로 밀어 넣지 말고 쉼표·"및" 자리에서 끊어 항목화한다(6단계 6항).
  한글은 표 안에서 단어 단위 줄바꿈이 잘 되지 않아 한 문장으로 넣으면 읽기 어려워진다.

## 수동 처리가 필요할 때
특수한 구조(값이 이미지 위 필드, 양식 필드 컨트롤 등)로 스크립트가 맞지 않으면, 압축을 직접 풀어
`Contents/section0.xml`을 확인하고 위 원칙(좌표 특정, 마지막 텍스트 노드에 덧붙이기, mimetype 규칙)을
손으로 적용한다. 자세한 배경과 예시 코드는 `references/technique.md`에 있다.
