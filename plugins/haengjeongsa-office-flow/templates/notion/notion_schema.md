# Notion 사건관리 표준 스키마

설치 마법사가 이 스키마대로 사무소의 Notion 워크스페이스에 세 개의 데이터베이스를 만든다.
생성 후 각 DB의 collection ID를 office_config.json 의 notion 항목에 기록한다.

## 1. 상담일지 (consult_db)

| 속성 | 형식 | 비고 |
|------|------|------|
| 상담제목 | 제목 | 「피상담자 사안 요약 상담」 꼴 |
| 상담번호 | 자동 ID | 접두어 YY |
| 피상담자 | 텍스트 | |
| 연락처 | 전화번호 | |
| 이메일 | 이메일 | |
| 주소 | 텍스트 | |
| 상담일시 | 날짜 | |
| 상담방식 | 선택 | 전화 / 채팅 / 방문 / 이메일 / 온라인폼 |
| 업무분류 | 선택 | 사무소 전문 업무 분야 목록으로 구성 |
| 상담내용 | 텍스트 | |
| 처분통지일 | 날짜 | 처분을 다투는 사안 |
| 법정기한 | 날짜 | 처분통지일 기준 계산값 |
| 개인정보동의 | 체크박스 | |
| 결과 | 선택 | 검토 후 회신 예정 / 위임계약 체결 / 종결 / 타기관 안내 |
| 결과상세 | 텍스트 | |
| 연결사건 | 관계 → 사건 DB | 수임 확정 시 연결. 중복 개시 방지의 기준 |

## 2. 사건 DB (case_db)

| 속성 | 형식 | 비고 |
|------|------|------|
| 사건명 | 제목 | 「의뢰인 사안」 꼴 |
| 사건ID | 자동 ID | 접두어는 설정의 case_prefix (기본 CS) |
| 업무분류 | 선택 | 상담일지와 동일 목록 |
| 세부업무 | 선택 | 사무소 사정에 맞게 구성 |
| 사건상태 | 선택 | 시작 전 / 진행 중 / 보완 / 완료 / 종결 |
| 접수일 | 날짜 | 수임 확정 당일 |
| 처분통지일 | 날짜 | |
| 수임료 | 숫자 | |
| 문서번호 | 텍스트 | 이 사건으로 발급된 문서번호 이력 |
| 개인정보동의 | 체크박스 | |
| 상담일지 | 관계 → 상담일지 | |
| 의뢰인 | 관계 → 의뢰인 DB | |

## 3. 의뢰인 DB (client_db)

| 속성 | 형식 | 비고 |
|------|------|------|
| 성명 | 제목 | 법인이면 상호 |
| 연락처 | 전화번호 | 기존 의뢰인 조회 키 (성명+연락처) |
| 이메일 | 이메일 | |
| 주소 | 텍스트 | |
| 구분 | 선택 | 개인 / 법인 / 단체 |
| 메모 | 텍스트 | |
| 사건 | 관계 → 사건 DB | |

## 운영 규칙

같은 피상담자의 상담일지가 이미 있으면 새 행 대신 기존 행에 덧붙일지 확인한다. 의뢰인은
성명과 연락처로 먼저 조회하여 같은 사람을 거듭 만들지 않는다. 상담일지의 연결사건이 차 있으면
사건이 이미 개시된 것이므로 새로 만들지 않는다.
